# Bajrang · बजरंग

रोज़ एक मिनट की हनुमान पूजा। एक टैप में पूजा पूरी, और लगातार साधना का हल्का सा अनुशासन —
बिना डाँटे, बिना लालच के।

A mobile-first devotional app for a daily 1-minute Hanuman ritual. Warm, calm, Hindi-first,
designed to feel like a temple app rather than a game.

भाषा: **हिंदी**, **বাংলा** और **English** — पहली स्क्रीन पर ही चुनिए (होम के ऊपर भी
टॉगल है, और सेटिंग्स में)। बदलते ही पूरा ऐप उसी भाषा में आ जाता है — सिवाय श्लोक
के, जो मूल देवनागरी में ही रहते हैं; उनके अर्थ हर भाषा में अलग हैं।

## चलाने का तरीका · Run

```bash
npm install
npm run dev      # लोकल डेवलपमेंट
npm run build    # प्रोडक्शन बिल्ड (+ PWA service worker)
npm run preview  # बिल्ड को देखिए
```

फ़ोन पर देखने के लिए: `npm run dev -- --host` चलाके उसी Wi-Fi पर फ़ोन से IP खोलिए।

## एक मिनट की पूजा · The flow that matters

यही वो हिस्सा है जिससे लोग टिकते हैं। कोई फ़ॉर्म पहले नहीं, सवाल बाद में।

```
शुरू करें  →  [ आवाज़ के साथ / बिना आवाज़ ]  →  60 सेकंड की पूजा  →  घंटी  →  नाम
                                                                        ↓
                                                          (वैकल्पिक) संकल्प + समय
```

1. **पहले सिर्फ़ "पूजा शुरू करें"** — नाम, संकल्प, समय, कोई खाता नहीं। नया उपयोगकर्ता बिना कुछ भरे सीधे पूजा कर सकता है।
2. **पूजा से पहले आवाज़ का चुनाव** — "आवाज़ के साथ" / "बिना आवाज़", दोनों बराबर। आखिरी चुनाव याद रहता है, और पूजा के दौरान 🔊 से बदला भी जा सकता है।
3. **पंक्ति-दर-पंक्ति रोशनी** — 60 सेकंड श्लोक की हर पंक्ति, अर्थ और मंत्र में बँट दिए जाते हैं (तौल `src/screens/Ritual.tsx` में `buildSteps`)। जो पंक्ति चल रही है वही सफ़ेद और चमकती है, पिछली सुनहरी, आगे वाली धुंधली। हर पंक्ति के नीचे उसका अपना प्रगति-रेखा, नीचे पूरे मिनट की घड़ी और पंक्तियों के बिंदु — इसलिए मिनट कभी खाली नहीं लगता।
4. **घंटी के बाद नाम** — पूजा पूरी होते ही पूछा जाता है: "हनुमान जी ने आपका नाम जान लिया।" छोड़ने का विकल्प भी है।
5. **फिर वैकल्पिक संकल्प + सुबह का समय** — दोनों छोड़े जा सकते हैं।

नाम पहले पूछने का एक और कारण यह था कि अगर उपयोगकर्ता ने छोड़ दिया तो वह कभी वापस नहीं आता — अब उसकी पहली पूजा ही पूरी हो चुकी होती है।

## https ज़रूरी है · Why HTTPS matters

रोज़ का संदेश, फ़ोन में इंस्टॉल, पूजा के दौरान स्क्रीण जली रहना, और WhatsApp वाला शेयर —
ये सब **सुरक्षित संदर्भ (HTTPS)** में ही काम करते हैं। `localhost` सुरक्षित माना जाता है,
लेकिन अपने फ़ोन से `http://192.168.x.x:4173` खोलेंगे तो ये सब चुपचाप नहीं होंगे।

इसीलिए `src/lib/env.ts` यह जाँचता है और सेटिंग में साफ़ बता देता है कि क्या चल रहा है
और क्या नहीं। अगर HTTPS पर नहीं हैं, तो ऐप "याद दिलाना चालू" होने का नाटक नहीं करता —
`reminderEnabled` ग़लती से `true` नहीं हो जाता, जिससे उपयोगकर्ता बाद में
"संदेश आया ही नहीं" नहीं कहता।

**लाइव करने का तरीक़ा:**

```bash
npx vercel --prod          # vercel.json पहले से मौजूद है
```

या कोई भी https होस्टिंग चलेगा (Netlify, Cloudflare Pages, GitHub Pages) —
बस `npm run build` का `dist/` सर्व करना है और सब routes पर `index.html` लौटाना है।

**फ़ोन पर जाँचते समय:** `localhost` से सब ठीक दिखेगा, पर असली अनुभव (संदेश, इंस्टॉल)
सिर्फ़ https पर मिलेगा।

## Android ऐप — भरोसेमंद संदेश

वेब (PWA) पर ब्राउज़र बंद होने पर JS नहीं चलता, इसलिए संदेश भरोसेमंद नहीं।
Capacitor से यह PWA एक **असली Android ऐप** बन जाती है, जहाँ संदेश Android के
AlarmManager पर लगता है — ऐप बंद हो, मारा जाए, फ़ोन रीस्टार्ट हो, फिर भी आएगा।
यही वो चीज़ है जिससे रोज़ की आदत बनती है।

**बनाने के लिए (एक बार):**

```bash
npm run cap:sync      # web बिल्ड + android पर कॉपी
npm run android:run   # फ़ोन/एमुलेटर पर चलाएँ
# या Android Studio में:
npm run cap:open
```

`android/` फ़ोल्डर रिपॉज़ में है, और `android/.gitignore` पहले से `build/`, `.gradle/`,
`local.properties`, `*.apk` छिपा देता है — यानी आपका SDK path या keystore लीक नहीं होगा।

**जो क्या लगाया गया है:**

| काम | कहाँ |
| --- | --- |
| रोज़ नियमित संदेश (`repeats: true`) | `src/lib/reminder.ts` → `scheduleNativeReminder()` |
| समय बदलने पर पुराना हटकर नया लगना | वही जगह — `cancel()` फिर `schedule()` |
| संदेश दिखने की इजाज़त (Android 13+) | manifest: `POST_NOTIFICATIONS` |
| ठीक समय पर पहुँचाने की अनुमति | manifest: `SCHEDULE_EXACT_ALARM`, `USE_EXACT_ALARM` |
| फ़ोन बंद होने पर संदेश ज़िंदा रहना | manifest: `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`; रीबूट पर प्लगइन का अपना `LocalNotificationRestoreReceiver` संदेश दोबारा लगाता है (`docs/PLAY-PRELAUNCH.md`) |
| Status bar का दीवे वाला आइकन | `android/.../res/drawable/ic_stat_icon.xml` |
| Exact alarm न मिलने पर ऐप खुद पूछे | सेटिंग में "अनुमति देने के लिए खोलें" बटन |

**वेब और ऐप में फ़र्क:** दोनों का UI एक जैसा है, पर सेटिंग में साफ़ लिखा है कि
आप किस दुनिया में हैं। PWA पर संदेश भरोसेमंद नहीं — फ़ोन की अलार्म का सुझाव भी वहीं दिया जाता है।

### ⚠️ जो मैंने जाँचा और जो नहीं

**जाँचा हुआ:** TypeScript + ESLint पास, वेब बिल्ड पास, `cap sync` पास (तीनों प्लगिन
मिले), manifest में 6 अनुमतियाँ मौजूद, और — सबसे ज़रूरी — **वेब ऐप अभी भी ठीक चलता है**
(पूरा पूजा-प्रवाह दोबारा जाँचा, कोई console error नहीं)।

**जाँचा नहीं हुआ:** इस मशीन पर Java, Android SDK, Gradle और adb — कुछ नहीं है।
इसलिए मैंने **APK बनाकर फ़ोन पर असली संदेश नहीं देखा**। पहली बार यह ज़रूरी है:

```bash
# JDK 17 और Android SDK (Studio वाला सबसे आसान) चाहिए
npm run android:run
# फिर: सुबह का समय चुनिए → चालू कीजिए → ऐप पूरी तरह बंद कर दीजिए → कल सुबह देखिए
```

और दो चीज़ें हाथ से जाँचनी होंगी: Android में "Alarms & reminders" की अनुमति,
और फ़ोन "battery saver" में हो तो भी संदेश ठीक समय आता है या नहीं।

  - `src/lib/shareCard.ts` — साझा करने वाला कार्ड सीधे canvas पर बनता है (हनुमान जी की सिंहावली सहित)

## अनुभव (UX) · क्या ख़ास है

- **पूजा के दौरान स्क्रीन जली रहती है** — Wake Lock API (`src/lib/device.ts`), 60 सेकंड में
  स्क्रीन बुझने से परेशान नहीं होना पड़ता; टैब लौटने पर अपने आप फिर जग जाती है
- **साँस का घेरा** — प्रगति घेरे के पीछे 7 सेकंड का धीमा pulse, ताकि मन शांत हो
- **हल्का कंपन** — पूजा पूरी होते ही `navigator.vibrate([14,60,24])`
- **टैब की जगह याद रहती है** — वापस लौटने पर स्क्रॉल वहीं से शुरू; उसी टैब पर दोबारा
  दबाने पर ऊपर चला जाता है
- **समय के हिसाब से नमस्कार** — शुभ प्रभात / नमस्कार / शुभ संध्या / शुभ रात्रि
- **नए उपयोगकर्ता को "० दिन" नहीं** — "नया शुरुआत 🪔" दिखता है (यह उम्मीद का ऐप है)
- **याद दिलाने की नम्र सलाह** — 3 दिन के बाद, सिर्फ़ एक बार, और "बाद में" छूट भी दिया जा सकता है
- **Install banner** — Chromium पर "लगाएँ" बटन, iOS पर Safari के निर्देश
- **बड़े अक्षर वाली जगह** — हर बटन/टॉगल कम से कम 56–58px, devanagari line-height 1.6–1.9,
  `prefers-reduced-motion` का पूरा समर्थन

## साझा करने वाला कार्ड · Share card

- 1080 × 1080 PNG, लगभग 1 MB — canvas से सीधे बनता है
- केसरिया ढाल (gradient), हनुमान जी की सिंहावली (मुकुट, प्रभामंडल, गदा, पूँछ, जोड़े हाथ), सामने दीवा
- नाम और स्ट्रीक `800` weight में मोटे अक्षर; लंबा नाम/बड़ी गिनती आ जाए तो अक्षर अपने आप छोटे होते हैं
- भेजने के तीन तरीके:
  1. **साझा करें** — Web Share Level 2, तस्वीर साफ़ फ़ाइल के रूप में (Android/iOS WhatsApp सीधे)
  2. **WhatsApp पर भेजें** — तस्वीर सहेजकर `wa.me` खोलता है
  3. **तस्वीर सहेजें / खोलें** — Blob URL से download; iOS Safari के लिए "खोलें" (Save Image)

## याद दिलाना · Reminder

संदेश: `🙏 [नाम], हनुमान जी का वार है — आज की पूजा 1 मिनट में पूरी करो`

`src/lib/reminder.ts` तीन तरीके आज़माता है:

1. App खुला हो तो `setTimeout` से समय पर (service worker के ज़रिए दिखाता है)
2. App बंद होकर खुले और समय बीत चुका हो तो एक बार "पछड़ा हुआ" संदेश
3. Chrome समर्थन दे तो Periodic Background Sync से registration

सेटिंग में संदेश का नमूना और "अभी संदेश भेजकर देखें" बटन भी है।
**सच्चाई:** ब्राउज़र बंद होने पर JS नहीं चलता, इसलिए सबसे भरोसेमंद तरीका फ़ोन की अलार्म है —
यही सेटिंग में लिखा है।

## बैकअप · Backup

ऐप में कोई सर्वर नहीं, कोई खाता नहीं — सब कुछ इसी फ़ोन के `localStorage` में है।
मतलब फ़ोन मिटाने पर, ब्राउज़र का डेटा साफ़ करने पर, या ऐप हटाने पर स्ट्रीक भी चली जाती है।

इसीलिए सेटिंग्स में **बैकअप** है:

- **डाउनलोड बैकअप** — एक JSON फ़ाइल (`bajrang-backup-YYYY-MM-DD.json`) जिसमें
  स्ट्रीक, क्षमा दिन, चालीसा यात्रा, कथा की स्थिति, संकल्प और भाषा — सब होता है।
  फ़ोन में Web Share हो तो सीधे वहाँ भेजा जाता है, वरना फ़ाइल सेव होती है।
- **बैकअप आयात करें** — वह फ़ाइल चुनिए; साधना वहीं से लौट आती है। आयात से पहले
  आँकड़े `sanitize()` से गुज़रते हैं, इसलिए टूटी या दूसरे ऐप की फ़ाइल साधना नहीं बिगाड़
  सकती — साफ़ इरारे के साथ रुक जाती है।
- सात दिन की साधना के बाद होम पर **एक बार** याद दिलाना आता है; दबाने पर या
  बैकअप लेने पर फिर नहीं आता।

कोई नया सर्वर नहीं जोड़ा गया — बैकअप भी उतनी ही ऑफ़लाइन है जितना बाक़ी ऐप।

## स्ट्रीक तर्क · Streak logic

`src/lib/store.ts` में — तारीखें हमेशा स्थानीय समय के `YYYY-MM-DD` रूप में (UTC नहीं):

- आज पूजा हो चुकी है और आखिरी पूजा **कल** थी → `streak + 1`
- एक या ज़्यादा दिन छूट गए → `streak = 1` (नया सिलसिला)
- आज पहले ही पूजा हो चुकी हो → गिनती दोबारा नहीं होती
- दिन छूटने पर कोई डाँट नहीं: होम पर "चिंता मत करो, फिर से शुरू करो 🙏"

## Android release build

**पहली बार** — signing key बनाएँ (यह repo में कभी नहीं आती):

```bash
bash scripts/make-keystore.sh
```

यह `bajrang-release.keystore` बनाता है और `~/.bajrang-keystore.properties` में
रखता है। **दोनों की एक नकल पासवर्ड मैनेजर में रखिए** — key खो गई तो Play Store में
नया ऐप नहीं भेजा जा सकता।

**फिर** — AAB बनाएँ (Play Store को यही चाहिए):

```bash
npm run cap:sync
cd android && ./gradlew bundleRelease
```

नतीजा: `android/app/build/outputs/bundle/release/app-release.aab`

जाँच: `keytool -list -v -keystore bajrang-release.keystore` → `Valid from` लगभग
27 साल दिखना चाहिए।

Play Console में यह भी भरना पड़ेगा: privacy policy URL, **Data safety → कोई डेटा
नहीं** (सब `localStorage` में है), content rating, और target SDK 35।

keystore न हो तो debug APK फिर भी बन जाता है — सिर्फ़ release बंधन छोड़कर।
